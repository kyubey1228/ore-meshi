# 待ち合わせチャット

募集が `MATCHED`（必要人数到達）、飯の予定が `ACTIVE` の間だけ、`MatchParticipant` に登録された参加者がテキストを送受信できます。店舗アカウントも参加者なら同じ条件です。最初の承認だけでまだ人数が足りない場合は待機表示になります。

成立ダイアログと募集詳細から `/matches/:id#chat` へ進めます。予定詳細にチャットを表示し、終了・キャンセル後は入力欄と履歴を非表示にします。既存の「飯終了」操作で閉じ、他の参加者の画面も次の更新で閉じます。予定日時を過ぎただけでは終了せず、既存の飯終了操作に従います。

## デプロイ

アプリの切り替え前に、対象の本番環境で `npm run db:deploy` を実行してください。`20260915010000_match_chat` はメッセージテーブル・外部キー・インデックスを追加するのみで、既存データは変更しません。E2Eで適用するのは隔離スキーマのみです。

## 制限・安全性

- 1通1〜1000文字、JSON本文最大8192バイト。HTMLは実行せずテキスト表示。
- 直近50件を約5秒ごとに取得。非表示タブと閉鎖後は更新停止。参加者・状態・履歴の読み取りは1 SQLのスナップショットで判定し、共有キャッシュに保存しません。
- 毎回認証・参加者確認。POSTはOrigin確認も必須です。
- 送信はSerializableトランザクションとMatch行の更新で終了処理と競合制御。再送IDは参加者・予定単位で一意にし、同じ送信の再試行を重複保存しません。新規送信は同じ参加者・予定で3秒間隔です。
- 終了は履歴の削除ではありません。終了後はAPIからも履歴を返しませんが、DBには保存されます。募集・予定・送信者が削除された場合は外部キーのCASCADEで削除されます。既に端末に届いた内容を取り消すものではありません。
- 添付画像、既読表示、新着メール通知、バックグラウンド通知は対象外です。

## 検証

`npm run build`、`npm run lint`、`node --import tsx --test tests/*.test.ts`。

本番ビルドのE2E: `E2E_PRODUCTION=true npm run test:e2e:isolated -- match-chat.spec.ts`。
匿名・部外者の拒否、CSRF、文字数、重複再送、連投、最新50件、成立待機、店舗参加者、3人の会話、スマホ幅、終了後の送信拒否・履歴非表示を確認します。

2026-09-15の確認結果: ビルド・型チェック・lint・単体テスト99件が成功。チャットE2EはAPI等5ケースと画面2ケースを分けて再実行し、全7ケース成功。既存の個人2人フロー3ケース、店舗＋複数個人フロー5ケースも成功しました。会話と終了のテストを独立させ、既存の45秒上限と各表示確認の10秒上限は維持しています。履歴テストおよび既存ランキング単体テストの比較時刻を固定し、実行速度で期待値が変わる問題を除去しました。本番DBへのマイグレーションは未実施です。
